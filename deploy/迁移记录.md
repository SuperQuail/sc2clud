# 老 Rust 数据迁移（2026-10-13）

> 用户原话：「旧站的dev也有自己的dev数据库，**做数据迁移来验证数据问题**」「在本机…是**老的 rust 实现版本的归档数据**」。

## 1. 源

```
backups/old-prod-2026-10-12/sc2clud.sqlite3     老 Rust 实现的**生产库**（SQLite，53 张表，576KB）
backups/old-prod-2026-10-12/legacy-dev.tgz     里面还有 3 个老 dev 的 SQLite（未迁）
```

## 2. 脚本

`deploy/migrate-legacy.py` —— 读老 SQLite，生成目标库的 SQL（UTF-8 直写，**不要用 PowerShell 的 `>`**：它写成 UTF-16 LE+BOM，psql 读不了，这个坑踩过一次）。

    python deploy/migrate-legacy.py out.sql     # 生成
    scp out.sql root@<host>:/tmp/                 # 46KB，base64 单条命令会撞命令行长度上限
    su postgres -c 'psql -v ON_ERROR_STOP=1 -d forum_dev -f /tmp/legacy.sql'

## 3. 表对应（逐个核对过，不是照猜）

| 老（SQLite） | 新（Postgres） | 处理 |
|---|---|---|
| `sections`(6) | `boards` | `key`->`slug`、`label`->`name`、`position`->`sort`、`archived_at` -> `status='archived'` |
| `users`(16) | `users` | `handle`->`username`、`display_name`->`nickname`、`role` 映射到 `roles.id`（super->4/superadmin） |
| `posts`(4) | `topics` + `posts`(floor=1) | **正文从 topics 拆到 posts 主楼**（新 schema 的正文在主楼） |
| `comments`(2) | `posts`（回复，floor 从 2 起） | `parent_id` 原样 |
| `post_likes`(3) | `likes` | `target_type='topic'`、`value=1` |
| `titles`(2) / `user_titles`(2) | 同名 | 直迁 |
| `sessions`(55) | **不迁** | 旧会话在新实现里必须失效 |
| `audit_log`(132) / `ai_secrets` / `blobs` / `files` | **不迁** | 见 §5 |

**保留老 id**（`OVERRIDING SYSTEM VALUE`，因为 id 列是 `GENERATED ALWAYS AS IDENTITY`），末尾 `setval` 把序列推到 `max(id)`。
`public_id` 用 **uuid5**（命名空间固定）—— 所以脚本可重复执行、重复跑是 no-op。

## 5. 明确**没有**迁的（都是取舍，写在这里免得下次当 bug 查）

1. **图片/BLOB 没迁** -> `users` 的三个头像字段一律 **NULL**（它们有指向 `images` 的外键；引用不存在的图会裂图甚至 500）。
   所以迁移后的用户在页面上是默认头像。要补图得把 `blobs`(11) + `prod-files.tgz` 里的文件也搬过去。
2. **老口令能直接登录**：老库用的是 **argon2id**（`$argon2id$v=19$m=19456,t=2,p=1$…`），与新实现同族 —— 但这条**没有实测过登录**（见 §6）。
3. `email` 为 NULL 的老用户按 `<handle>@example.com` 补（新 schema 里 email NOT NULL）。**这是个占位值，不能用来收信。**
4. `audit_log`(132) / `sessions`(55) / `ai_secrets` / `counters` 不迁。

## 6. 已知异常与没验到的

1. **老用户的 id 没有被保留**：新库里是 84–99，而老库是 1,3,5,9–21。
   跨表引用仍然**一致**（5 组关系 0 悬空，topics 的作者解析正确），但「老 id 与新 id 的对应关系」丢了。
   如果以后有按老 id 对账的需求，得重新生成一次映射表。**这是本脚本要修的地方。**
2. **没有实测「用老口令登录」** —— 那需要一个老用户的明文口令，我没有。
3. `legacy-dev.tgz` 里那 3 个老 dev 库**没迁**（用户说的是 dev 库；生产库的内容已覆盖同样的话题）。
