## 3. 表对应（逐个核对过）

| 老（SQLite） | 新（Postgres） | 说明 |
|---|---|---|
| `sections`(6) | `boards` | `key` 映射到**设计 slug**：vanilla_mod→vanilla-mod、custom_campaign→custom-campaign、tool_player→tool-player、tool_dev→tool-dev；`emperor` 在设计里没有对应物，**保留原名**（真数据） |
| `users`(16) | `users` | **保留老 id**（`OVERRIDING SYSTEM VALUE`）；`handle`→`username`、`display_name`→`nickname`；role: super→superadmin(4) |
| `posts`(4) | `topics` + `posts`(floor=1) | 新 schema 里正文属于**主楼**，所以从 topics 拆出去 |
| `comments`(2) | `posts`（回复，floor≥2） | `parent_id` 原样 |
| `post_likes`(3) | `likes` | `target_type='topic'`、`value=1` |
| `titles`(2) / `user_titles`(2) | 同名 | 直迁 |
| **`data/blobs` 里的图片** | `images` + 实例的 `data/images/<ab>/<cd>/<hash>` | **布局两边一致**，所以文件直接放进去就能被找到 |
| `sessions`(55) / `audit_log`(132) / `ai_secrets` | **不迁** | 旧会话必须失效；审计与密钥不属于新站 |

## 4. 三个必须记住的坑（都踩过）

1. **`images` 只收四种 mime**（`ck_images_mime`：png/jpeg/gif/webp）。老库的 `blobs` 里混着 `.txt` ——
   按 `application/octet-stream` 塞进去会让**整笔事务回滚**。现在的脚本只登记 Pillow 认得出的图（本次跳过 3 个非图片）。
2. **`id` 列是 `GENERATED ALWAYS AS IDENTITY`** —— 要给老 id 就必须 `OVERRIDING SYSTEM VALUE`，否则第一张表就报错。
3. **`backups/` 是 root-only**：`su postgres -c pg_dump -f /srv/.../backups/x.dump` 会 Permission denied。
   先写 `/tmp` 再由 root 搬进去。（而且这个失败在 `cmd && echo` 结构里**不会被 `set -e` 拦住**，会继续往下跑 —— 所以备份要先单独确认成功。）
