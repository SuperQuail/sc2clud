## 4. 三个必须记住的坑（都踩过）

1. **`images` 只收四种 mime**（`ck_images_mime`：png/jpeg/gif/webp）。老库的 `blobs` 里混着 `.txt` ——
   按 `application/octet-stream` 塞进去会让**整笔事务回滚**。现在的脚本只登记 Pillow 认得出的图（本次跳过 3 个非图片）。
2. **`id` 列是 `GENERATED ALWAYS AS IDENTITY`** —— 要给老 id 就必须 `OVERRIDING SYSTEM VALUE`，否则第一张表就报错。
3. **`backups/` 是 root-only**：`su postgres -c pg_dump -f /srv/.../backups/x.dump` 会 Permission denied。
   先写 `/tmp` 再由 root 搬进去。（而且这个失败在 `cmd && echo` 结构里**不会被 `set -e` 拦住**，会继续往下跑 —— 所以备份要先单独确认成功。）

## 6. 与 `forum seed`（合成演示数据）的关系 —— **两者共存，不是重复实现**

**我先删了 `forum seed`，那是判断错了，已恢复。** 记在这里免得后人重复这个错：

- 我删它的理由是「与迁移重复」。那个理由成立的前提是「迁移用下划线 slug、seed 用连字符 slug，两套键空间撞车」——
  而**同一批工作里**我已经把迁移映射到设计 slug（`vanilla_mod` → `vanilla-mod`），两边于是落在**同一套 slug** 上：
  同一 slug 会合并成一行，**不再有重复分区**。
- 而且两者覆盖的事不同：迁移是**4 篇真帖**（用户的旧站数据，这一轮的目的）；
  seed 是**照设计的量**（25 主题 / 75 回复），用来验分页、搜索、个人主页列表 —— 4 篇真帖验不了这些。
- **所以：共存。** 迁移不动 seed 的数据，seed 也不动迁移的 4 篇真帖。

**另一份被清掉的**：`deploy/migrate/import_legacy.py`（另一个 agent 并行写的导入脚本，与本文档描述的脚本重复）——
保留的是**验证过的那份**（`deploy/legacy-migration.sql`，含老 id 与头像）。

**教训（写进房间规矩）**：删别人的实现之前，先确认它与你以为重复的那个东西，**真的覆盖同一件事**。

## 7. 迁移施工者的完整回报里，几条必须留档的（2026-10-13 补）

### 7.1 三个「导入器通用坑」（不是这一份数据的问题）

1. **派生计数列必须自己重算**：`reply_count` / `like_count` / `last_reply_at` 是**应用在写路径上维护的缓存**
   （`forum/pgsql/posts.go` 的 `RecountTopic`、`votes.go` 的 `likeSetSQL`），任何「直接 INSERT」的导入都会得到 0。
   更糟的是用户点一次赞就让它从 0 变 1 —— **数字永久漂移**。导入后必须重算。
2. **写入顺序必须按 `created_at`**：楼层分页的游标键是 `posts.id`，而代码注释假设「id 与 created_at 同序」。
   先写主题再写回复，会让后写的回复 id 小于正文，回复排到正文前面。
3. **`boards.slug` 没有格式 CHECK**（只有 `varchar(32) UNIQUE`）—— 下划线 slug 能插进去、不报错，
   这类错**只有人眼看列表才发现**（也正是「两套键空间并存成两倍分区」那次）。

### 7.2 迁移造成的一处**功能性丢失**（需要决定要不要补）

老 `sections` 有 `post_min_role` / `reply_min_role` 两档门槛（`admin` / `developer` / `member`）；新站只有**一个数字门槛** `boards.min_post_level`。
本次把 6 个分区**全部**映射成 `min_post_level = 0` —— 于是**公告区原本「只有管理员能发帖」这条约束在迁移后消失了**。
回帖门槛在新站无处安放（老数据里回帖门槛全是 member，所以只在公告区丢了一档）。

### 7.3 其它值得记的

- **`todayStart()` 硬编码 UTC+8**（`forum/pgsql/topics.go`）——「今日 X 帖」换时区或跨零点会对不上，与迁移无关但是个真隐患。
- **老站的 13 个 `site_texts` 键全部丢弃**（新站 `SettingSpecs` 是唯一真源，没有这些开关）——
  **等于把老站的 AI 审核与邮件节流配置整块留在了旧站**；要在新站恢复得先有对应功能。
- **老口令静态分析上能登录**：老库是 argon2id PHC，新站 verifier 从串里读参数 → 能登，登录后按新参数 rehash。**没有明文口令可实测**。
- **`example.com` 与 `.invalid` 都是保留域**（RFC 2606），拿它当占位邮箱不会真投出去 —— 这条施工者说反了，但结论（占位收不到信）不变。
- **12 个 `demo-*` 探针用户被误删**（施工者清除语句没先列名单）—— 那是 DevRoom 假数据名册的，应由 seed 那条路补，不要手工造。

### 7.4 评论不渲染（**本轮最该记住的发现**，尚未修）

现象：`/dev/t/<uuid>` 页面写「评论 1」，评论列表 0 条（DOM 容器 innerHTML 长度为 0），而接口 200 且返回 2 条楼层。
根因：**契约不一致** —— 顶层楼层的 `parent_id` 后端发 `""`（`dto.go:118` 的 `PostDTO.ParentID` 是 `string`，注释「空串 = 顶层」，`map.go` 用 `deref()` 把 NULL 变空串），
而前端声明 `parent_id: string | null`（`web/src/lib/api/forum.ts:98`）并按 `=== null` 过滤（`routes/_parts/mappers.ts:43`）→ roots 为空。
`IssueCommentDTO.ParentID` 同写法，issues 评论同病。

**为什么测试没抓到**：Go 侧断言的是 `PostDTO.ParentID` 字段（空串）、前端 mock 里写的是 `null` ——
**两边各自的测试都过，序列化那一层没人测**。修法：`dto.go` 两处 `ParentID string` → `*string` + **一条 JSON 级断言**。
