## 1. 目标与不变量

### 1.1 一句话

用一套**单一渲染器**（React）重写整个前端：页面结构 100% 由 React 产出，交互不再散落在模板、内联脚本、SSR 模板与前端岛之间。

### 1.2 从后端方案继承的硬约束（不可协商）

| 约束 | 来源 | 对前端的强制影响 |
|---|---|---|
| 服务器 2 核 / 2 GB，只跑一个后端进程 | 后端方案 §1.2 | **不引入常驻 Node 进程**（不做 Node SSR）；不引入会显著吃内存的构建期工具 |
| 图片字节不进后端进程，nginx 直出 | 后端方案 §10 | 前端只拿 `/img/<hash>` URL，不做图片代理、不做前端 CDN |
| 接口前缀 `/api/v1`，Cookie 会话，Origin 校验防 CSRF | 后端方案 §9.2 / §9.3 | 数据层必须是单一 HTTP 客户端；默认同域部署 |
| 对外 ID 一律 public_id | 后端方案 §6.5 | 前端类型里的 id 一律是 string，禁止出现自增数字 id |
| 金额一律整数分 | 后端方案 §14.7 | 前端展示时才除 100，禁止用浮点做金额运算 |
| 时间一律 RFC3339 UTC | 后端方案 §14.4 | 前端只在展示层转本地时区，禁止把本地时间回传 |

### 1.3 前任失败给出的硬性要求（来自原项目失败复盘）

新前端必须做到，且每条都有可检查的门禁（见第 11 章）：

1. 一个页面**一个入口**：交互逻辑只属于 `web/src`，模板里没有业务 JS（本项目根本没有模板）。
2. 数据协议**单一真源**：请求/响应类型与 URL 只允许在 `src/lib/api` 里出现一次。
3. 请求/响应字段名与后端契约逐字对齐；**禁止手写第二份字段名**（旧站 422 类缺陷的根因）。
4. 预算**一个口径**（gzip 后），一个数字，一个门禁。
5. 产物**单一来源**：一条命令从干净检出产出可部署物；缺产物必须启动即失败，不允许运行期 404。
6. 规则要**会红**：每条架构规则配一个能失败的检查，检查跑在实际会合入的分支上。

## 2. 渲染形态（决策 D1，【待确认】但已按此实施）

### 2.1 决策

**纯客户端渲染的 SPA（Vite + React），公开页面的首屏 meta 由 Go 注入。**

- 静态产物由 nginx 直接托管（`/assets/*`）。
- 所有 **HTML 文档请求**由 Go 处理：它读构建产物里的 `index.html`，把 `<title> / description / canonical / Open Graph / JSON-LD` 填好，连同 `<div id="root">` 与同一份 JS 引用一起返回。
- **body 结构 100% 由 React 渲染**。Go 侧只填 `<head>`，不产出任何页面结构。

### 2.2 为什么不是别的

| 方案 | 为什么不选 |
|---|---|
| Node SSR（Next.js / React Router framework 模式） | SEO 最好，但要多一个常驻 Node 进程（约 100–150 MB RSS）与一套 Node 部署，与后端 §1.2「只跑一个进程、不引入外部常驻组件」直接冲突；2 GB 机器上这笔账不划算 |
| 服务端模板（askama / html/template）+ 前端岛 | **这就是旧站的路**。两套结构必然漂移（旧站实测：模板 textarea 与编辑器内容不一致）。重写的第一目标就是消灭它，不能换个语言再抄一遍 |
| 纯 SPA，连 meta 都不做 | 分享到 QQ / Discord / 微信的卡片全站一样，标题没有区分度，搜索引擎零收录。成本极低但不做，等于自愿放弃流量入口 |

### 2.3 代价与升级路径（诚实记账）

- **代价**：帖子正文不被搜索引擎抓取。meta 壳能保证「分享卡片正确、标题正确、canonical 正确」，但不等于正文 SEO。
- **升级路径**：如果日后确实需要正文 SEO，把 Vite SPA 换成 React Router framework 模式（或 Next.js）——**页面组件、`src/lib/api`、`src/ui`、`src/features` 全部不动**，只换入口与路由声明方式。因此现在必须遵守一条：**路由组件不许直接从 `window`/`document` 取数据**，否则换渲染模式时会全线返工。

### 2.4 Go 侧 meta 壳的规矩

- 壳只做三件事：填 meta、给正确的 HTTP 状态码（404 也要是 404，不是 200 + 前端兜底）、引用构建产物。
- 壳还要按实例注入**运行期前缀**：把 `index.html` 里的 `<base href="/" />` 改成 `<base href="/dev/" />`；前端以 `document.baseURI` 为唯一来源（`src/lib/base.ts`）算 Router basename 与 API 前缀。
- **为什么用 `<base href>` 而不是 `base: './'`**：后者在深链接（`/dev/t/123`）下会把资源解析成 `/dev/t/assets/…` 而 404；`<base href>` 是绝对前缀，正好修掉这个坑（盲审 F01）。
- Vite 侧必须写 `base: './'`（相对），资源 URL 才会跟随 `<base href>`；写成绝对 `/assets/` 的话，dev 实例会去加载生产的前端产物。
- 壳读取的 HTML 来自 `web/dist/index.html`（**运行期从磁盘读，不用 go:embed**）。理由：编译期嵌入会把「前端构建必须先于后端编译」变成隐性依赖，旧站正是在这条链上踩过「新面板全 404」。运行期读 + **启动时检查文件存在，缺了就拒绝启动**，把这类故障从「运行期 404」变成「启动失败」。
- 配置项：`web.dist_dir`、`web.serve_shell`（开发期由 Vite 提供 shell 时关闭）。
- 壳**禁止**渲染任何 body 内容；一旦发现 Go 侧出现页面结构，就是回退到旧站架构，评审直接打回。

### 4.1 依赖方向（违反即评审打回）

    routes → features → (ui, lib)
    ui     → lib
    lib    → 无（不 import features / routes / ui）

1. `lib/` 是最底层，禁止 import 任何上层。
2. `features/x` 禁止 import `features/y`。需要对方东西时，提到 `ui/`（纯展示）或 `lib/`（纯逻辑），而不是横向依赖。
3. `routes/` 只做组装：取路由参数 → 调 feature 的 hook → 摆布局。**routes 里不许出现 fetch、不许写业务规则**。
4. `ui/` 是纯展示：只接收 props，不知道 API、不知道路由。
5. **`fetch` 只允许出现在 `lib/api/client.ts`**。其它任何文件出现 `fetch(` 即失败（用 ESLint 规则 + 门禁脚本盯住）。

## 5. 数据层（全站唯一出口）

### 5.1 响应包络（与后端 §14.4 逐字对齐）

    成功:  { "data": { … } }
    列表:  { "data": [ … ], "next_cursor": "…" }
    失败:  { "error": { "code": "topic.locked", "message": "主题已锁定", "request_id": "…" } }

`client.ts` 负责三件事：拼 URL、带 Cookie、把失败统一转成 `ApiError`。

    // src/lib/api/client.ts（骨架，实际实现见仓库）
    export class ApiError extends Error {
      constructor(readonly status: number, readonly code: string, message: string,
                  readonly requestId?: string, readonly fields?: Record<string, string>) { super(message) }
    }

    type Req = { method?: 'GET'|'POST'|'PATCH'|'DELETE'; body?: unknown; query?: Record<string, unknown>; signal?: AbortSignal }

    // 全站唯一的 fetch 调用点
    export async function api<T>(path: string, req: Req = {}): Promise<T>

规则：

- `credentials: 'include'` **必须**：会话是 HttpOnly Cookie，前端拿不到 token（这是有意的）。
- **不做 CSRF 令牌**：默认同域部署，后端靠 SameSite=Lax + Origin 校验（后端 §9.3）。跨站部署开启时按后端公告同步改，前端只改这一处。
- 请求体一律 `application/json`。**禁止表单编码**：旧站的 422 类缺陷全部来自「控件发的内容类型与后端提取器不匹配」。
- 200/201 解析 `data` 后返回；204 返回 `undefined`。
- 非 2xx：抛 `ApiError`，字段从 `error` 里取。**禁止**只读 `response.status` 丢掉 `code`（`code` 是 UI 行为的依据）。
- 网络故障（`TypeError`）转成 `ApiError(0, 'network')`，UI 才能区分「网断了」与「服务端 500」。

### 5.2 错误码 → UI 行为（集中在一处）

| 状态 / code | UI 行为 |
|---|---|
| 401 `common.unauthorized` | 清 `['me']` 缓存；弹登录框并记住回跳地址（**不要整页跳转走掉用户输入**） |
| 403 `common.forbidden` | 提示「没有权限」；若发生在路由级渲染，换成 403 页面 |
| 404 `common.not_found` | 404 页面（详情页）；列表里的单条失败只提示不整页跳 |
| 409 `common.conflict` | 提示「数据已变化，请刷新」并让相关 query 失效 |
| 429 `common.rate_limited` | 读 `Retry-After` 头，按钮进入倒计时禁用，提示剩余秒数 |
| 400 `common.invalid_input` + `fields` | 把 `fields` 映射到表单字段错误（**唯一**的表单错误来源） |
| 其它 5xx | 「服务器错误」+ 显示 `request_id`，让用户报错时能对日志 |

### 5.3 query key 与失效

    // src/lib/query/keys.ts
    export const qk = {
      me:        () => ['me'] as const,
      boards:    () => ['boards'] as const,
      topics:    (f: TopicFilter) => ['topics', f] as const,
      topic:     (id: string) => ['topic', id] as const,
      posts:     (id: string) => ['topic', id, 'posts'] as const,
      profile:   (handle: string) => ['profile', handle] as const,
      notif:     (f: NotifFilter) => ['notifications', f] as const,
      unread:    () => ['notifications', 'unread'] as const,
      search:    (q: string, t: string) => ['search', t, q] as const,
    }

- **禁止**在组件里手写 key 字符串数组：key 只有一处定义，失效才可能正确。
- 写操作成功后按「谁受影响」失效，不搞全量 `invalidateQueries()`：

| 动作 | 失效 |
|---|---|
| 发帖 | `topics(filters)` 全部 + `boards()` |
| 回复 | `posts(topicId)` + `topic(topicId)` |
| 点赞 / 收藏 | 只改该条的乐观值，失败回滚 |
| 编辑资料 / 换头像 | `me()` + `profile(handle)` |
| 读通知 | `unread()` + `notif(filters)` |

- `staleTime`：列表 30 秒、详情 60 秒、`me` 5 分钟、静态（版块表）10 分钟。**默认值必须在 `lib/query/client.ts` 里写死**，不要在组件里各写各的。
- 分页一律 `useInfiniteQuery` + `next_cursor`（后端 §6.9：不用 OFFSET）。**禁止**自己做页码拼接。
- 乐观更新只允许用于**幂等开关**（点赞、收藏、已读）。发帖、回复、支付相关一律等服务器返回。

### 5.4 会话与权限

- 登录态的唯一真源是 `GET /api/v1/me`：

    // src/features/auth/use-session.ts
    export function useSession() {
      const q = useQuery({ queryKey: qk.me(), queryFn: fetchMe, retry: false, staleTime: 5 * 60_000 })
      return { principal: q.data ?? null, isLoggedIn: q.data != null, isLoading: q.isPending }
    }

  **不要**在 localStorage 里存 token 或「已登录」标志：Cookie 是 HttpOnly 的，任何前端副本都会与真相漂移。
- 登录 / 登出成功后：`queryClient.clear()`（清掉上一个账号的一切缓存）。
- 权限：后端在 `/api/v1/me` 里返回 `perms: string[]` 与 `is_super`。`useCan('post.delete_any')` 只用来**决定显不显示**。

    **前端权限不是安全边界。** 隐藏按钮是为了界面干净，不是为了安全；后端必须独立判定（后端 §9.8）。禁止写「因为按钮没显示所以后端不用查权限」这种注释。

- 未登录用户看到需要登录的入口：显示按钮，点击后弹登录框（不要直接隐藏，否则用户不知道功能存在）。

## 6. 路由表

路由定义**只有一处**：`src/app/router.tsx`。页面级代码分割用 `React.lazy`，**公开首页与帖子页不分割**（首屏路径）。

| 路径 | 页面 | 登录 | 权限点 | 主要接口 |
|---|---|---|---|---|
| `/` | 首页信息流 | — | — | `GET /topics`、`GET /boards` |
| `/b/:boardSlug` | 版块列表 | — | — | `GET /topics?board=` |
| `/t/:topicId` | 帖子详情 + 回复 | — | — | `GET /topics/:id`、`GET /topics/:id/posts` |
| `/new` | 发帖 | ✔ | `post.create` | `POST /topics` |
| `/u/:handle` | 个人主页 | — | — | `GET /users/:handle` |
| `/search` | 搜索 | — | — | `GET /search` |
| `/download` | 启动器下载 | — | — | `GET /launcher/releases` |
| `/login` `/register` `/forgot` `/reset` | 认证 | — | — | `/auth/*` |
| `/settings` | 个人设置（资料 / 头像 / 密码 / 会话 / 收款码） | ✔ | — | `/me/*` |
| `/notifications` | 通知中心 | ✔ | — | `/notifications` |
| `/messages` `/messages/:handle` | 私信（一对一） | ✔ | — | `/messages`；**standard 档 SSE + 30s 轮询兜底，small 档轮询 5s / 未读 30s** |
| `/u/:handle` | 个人主页（含头衔、等级、打赏统计） | — | — | `/users/:handle` |
| `/admin/*` | 管理后台 | ✔ | 各自权限点 | `/admin/*` |
| `*` | 404 | — | — | — |

规则：

- **URL 即状态**：筛选、排序、分页游标、tab 全部进 `searchParams`。禁止用 `useState` 存「当前在第几页」。理由：可分享、可后退、刷新不丢。
- 路由守卫只做**体验**（未登录时弹登录框），不做安全：真正的拒绝在后端。
- `/admin/*` 在路由层声明所需权限点，缺权限直接渲染 403 页面，不发无谓请求。
- 页面组件禁止直接读 `location.search` 字符串再自己 parse：用路由提供的解析后的 `searchParams`。

## 7. UI 层

### 7.1 设计令牌（唯一颜色来源）

沿用旧站设计稿已定的令牌（`shots/design/c/notes.md` 与 `b/notes.md`），落到 `src/styles/tokens.css`：

    浅色: 主色 #2563eb · 正文 #1f2430 · 线 #e5e7eb · 卡面 #fff
    深色: 正文 #e6e8ef · 线 rgba(255,255,255,.12) · 卡面 #161a26 · 主色 #8fb0ff

- 首次渲染前由 `index.html` 里**唯一允许的一段内联脚本**设好 `data-theme`（否则深色用户会看到白闪）。这段脚本是例外，必须写进文档并在评审时说明。
- 跟随系统默认，用户手动选择后存 `localStorage`，尊重 `prefers-reduced-motion`。
- 基础控件视觉采用**方案 C（极简下划线 / 细边框）**：静态几乎「没有控件」，聚焦靠下划线加粗与字重，错误态常驻可见。理由：论坛主体是阅读，克制的一版噪声最低（方案 B 的填充式 Material 3 更适合表单密集的后台，可作为后台的局部变体）。**【待确认】**
- 圆角 / 高度 / 间距一律取令牌，禁止就地写魔法数字。

### 7.2 `src/ui/` 基础件

| 控件 | 来源 | 说明 |
|---|---|---|
| Button / Input / Textarea / Select / Checkbox / Radio / Toggle | **Ring UI** | 直接用 Ring UI 的组件，不自己实现 |
| Dialog / Popup / Dropdown / Tooltip / Tabs | **Ring UI**（Popup、Dropdown、Tooltip、Tabs 都有对应件） | 键盘与焦点行为由 Ring UI 负责 |
| Avatar / Badge / Tag / Progress | **Ring UI** | — |
| 表格 / 骨架 / 空状态 | Ring UI 有表格件；骨架与空状态自建（`src/ui/`，纯展示） | — |
| 布局 / 间距 / 栅格 / 响应式 | **Tailwind 工具类** | 不写自定义布局 CSS |
| 图标 | **lucide-react** | 统一从这里引；禁止手抄 SVG |

规则：

- **先查 Ring UI 有没有**；没有才在 `src/ui/` 自建，并且只写外观与组合，不重写键盘/焦点/ARIA。
- Tailwind 负责布局与间距，Ring UI 负责控件外观——**两者不要在同一个属性上打架**（见 §7.6 的加载顺序）。

规则：

- 新增控件前**先查这里有没有**；没有就先加基础件，不许在业务里现写一个。
- 图标统一用 **lucide-react**（用户已定）。禁止另引图标库、禁止手抄 SVG 路径。
- 无障碍是硬要求：label 关联、`:focus-visible` 可见焦点、`aria-invalid`、Esc 关闭、焦点陷阱（Radix 负责）、颜色对比 ≥ 4.5:1。**不允许**为了好看去掉焦点环。

### 7.6 CSS 与控件库的分工（实测结论）

**结论：清单里的三套东西（Tailwind / shadcn-ui / Ring UI）可以共存，但要划清边界，否则就是三套设计语言打架。**

| 层 | 归属 |
|---|---|
| 控件基座（Button / Input / Select / Table / Popup …） | **Ring UI**（默认，先查它有没有） |
| 补充 | **shadcn/ui**：Ring UI 没有的控件，或 Ring UI 的实现确实别扭时 |
| 布局、间距、响应式 | Tailwind 工具类 |
| 图标 | lucide-react（shadcn 的默认图标库，正好一致） |

**Ring UI 作为核心的三条实测事实**（2026-10-12）：① 必须引聚合 `components/style.css`——`-built` 包的组件**不带自己的 CSS**，不引就是裸 HTML；② `core-js` 是它的 peer 但**不要装**：只有未导入的组件（auth 等）才用它，装了会被 pnpm 11 的未批准构建脚本拦下整个 `pnpm install`；③ **React 18 / 19 下都能跑**：`src/ui/ring-ui.test.tsx` 用真实渲染验证了 Button 点击与 Input 受控（React 19.3 与 18.3.1 下均通过；产品最终用 React 18，与 Ring UI 同代）。

**shadcn 的落地方式**：它的 CLI 在本机跑不起来（自带的 MCP 依赖要 `zod/v3`，与项目的 zod 4 冲突），所以 `components.json` 与首批组件（button / input / label）是**按 shadcn 规范手工落的**——这正是 shadcn 的设计（源码进仓库）。以后 CLI 能用了直接 `shadcn add <组件>` 继续加。

| 项 | 实测结果 |
|---|---|
| 源包 `@jetbrains/ring-ui` | **构建失败**：它在 `.js` 文件里直接写 JSX，Vite/rolldown 解析不了（`button.js:45` 就是 `const content = (<>)…`） |
| 预编译包 `@jetbrains/ring-ui-built` | **构建成功**：1936 个模块，产物 JS 172.11 kB（gzip **57.37 kB**）、CSS 196.13 kB（gzip **28.72 kB**） |
| 不引聚合 `style.css` | CSS 降到 5.89 kB（gzip **1.99 kB**）——组件会各自带上自己的 CSS |
| React 版本 | Ring UI 的 peer 是 `react >= 18`。**产品已统一到 React 18.3.1**（实验室与产品同版本，减少一处差异） |
| peer 依赖 | Ring UI 声明 `core-js` 与 `webpack` 为 peer；**本项目用 Vite，不要装 webpack**，core-js 按需 |

**必须遵守的三条**：

1. **只能用 `@jetbrains/ring-ui-built`**，不许引源包。这不是偏好，是构建能不能过的问题。
2. **加载顺序：Tailwind 在前，Ring UI 的样式在后**。两者都带全局样式（Tailwind preflight 会重置 `button`/`input`/`h1..h6`/`ul` 等），Ring UI 是控件基座，冲突时以它为准；布局类工具（`flex`/`gap-*`/`p-*`）特异性更高，不受影响。
   ```
   import './styles.css';                                  // Tailwind（含 preflight + 令牌）
   import '@jetbrains/ring-ui-built/components/style.css'; // Ring UI 全局（按需，见下）
   ```
3. **按需引样式**：优先让组件自带的 CSS 生效；只有在确认缺变量/主题时才补全局 `style.css`（它一次就是 28.7 kB gzip，几乎吃掉整个 CSS 预算）。接入时用 `pnpm gate:budget` 卡住。

**分工边界**（避免两套设计语言打架）：

| 层 | 归属 |
|---|---|
| 控件外观（按钮、输入、下拉、弹窗…） | Ring UI |
| 布局、间距、栅格、响应式 | Tailwind 工具类 |
| 站点品牌色与深浅色令牌 | `src/styles/tokens.css`，**Ring UI 的主题变量在这里被覆盖**（不直接改 node_modules） |
| 图标 | lucide-react |
| 自建控件 | 只放 `src/ui/`，且仅在 Ring UI 确实没有时 |

**实验室**：`web/tools/ring-ui-lab/`（独立 package，不参与产品构建）。跑法：`cd web/tools/ring-ui-lab && pnpm dev`。它存在的意义就是**下次升级 Ring UI 时先在这里验一遍**，而不是直接改产品。

### 7.3 表单约定

- 表单用 **react-hook-form**，校验用 **zod + `zodResolver`**；schema 与 `lib/api` 里的类型同处（一份 schema，类型由 `z.infer` 推导）。
- 服务端返回的 `error.fields` 用 `setError` 回填到对应字段，**优先于本地校验结果**。
- 提交前用 zod 校验（`lib` 里定义 schema，与 API 类型同处）。服务端 `fields` 错误优先于本地校验结果。
- 提交中禁用按钮并显示进度；**禁止**重复提交（旧站「重复点赞」「重复下单」类问题的前端一半）。
- 成功/失败的提示统一走一个 `toast`；**禁止**用 `alert()`。

### 7.4 图片上传（本站唯一的字节入口）

- 头像：**浏览器里压到 ≤ 64 KB 再上传**（canvas 循环降质量/尺寸），正方形裁剪由用户框选，输出建议 256×256。服务端会再校验一次 —— 前端压缩是省带宽，不是可信边界。
- 帖子配图：单张 ≤ 2 MB，每贴 ≤ 9 张；上传前校验魔数（读文件头，不看扩展名）。
- 上传失败要能重试单张，不要整批重来。
- 展示：`loading="lazy"` + 固定宽高比容器（防 CLS）；URL 就是 `/img/<hash>`，**不做前端图片代理、不做缩略图参数**。

### 7.5 Markdown

- 展示：只渲染后端给的 `content_html`，**全站唯一一处 `dangerouslySetInnerHTML`**，且必须在 `ui/markdown.tsx` 里，附注释说明「内容已由后端 bluemonday 清洗」。
- 编辑器预览：调 `POST /api/v1/markdown/preview`（后端同一渲染器）。**禁止**在前端引 markdown 库再实现一遍。
- 链接安全：渲染后的外链统一加 `rel="noopener noreferrer"`（在 `markdown.tsx` 里做一次）。

## 8. 状态管理边界（一句话规则）

| 状态种类 | 放哪 | 禁止 |
|---|---|---|
| 服务端数据 | TanStack Query | 复制到别的 store |
| 登录者与权限 | Query 的 `['me']` | localStorage 里存「已登录」 |
| 筛选 / 分页 / tab | URL searchParams | useState 存可分享状态 |
| 表单输入 | 组件内 useState | 提到全局 |
| **跨组件的纯 UI 状态**（主题、侧栏、toast 队列、未发送草稿） | **Zustand store** | 把服务端数据复制进来 |
| 只有单个组件用的 UI 状态 | 组件内 useState | 为了「统一」也塞进 Zustand |

**判断方法**：这个状态刷新页面后应该还在吗？应该 → URL；不应该 → 组件内。**服务端有的数据永远不复制。**

**Zustand 的三条硬规矩**：① 一个 store 一个文件，放 `src/lib/store/`；② **禁止把 TanStack Query 的数据复制进 store**（那就是把服务端状态存两份，旧站根因 2 的前端版）；③ store 里只放「刷新页面丢了也无所谓」的东西——要留的进 URL 或后端。

## 9. 性能预算与门禁

### 9.1 预算（唯一口径：**gzip 后**；CI 与文档共用这一列）

| 项 | 上限 | 说明 |
|---|---|---|
| 首屏 JS（含 React、路由、Query） | 150 KB | 超出必须说明并降级依赖 |
| 单个懒加载路由 chunk | 60 KB | 管理后台允许 90 KB |
| 首屏 CSS | **40 KB**（gzip） | 其中 Ring UI 的聚合样式表占 ~30 KB，改动前先看 §7.6 |
| 单页请求数（首屏） | ≤ 10 | 数据靠 2–3 个 query 合并，不要每块一个请求 |
| LCP（4G 模拟） | ≤ 2.5 s | — |
| CLS | ≤ 0.1 | 图片必须有宽高比容器 |

### 9.2 门禁脚本

- `scripts/check-size.mjs`：**> 500 行的源码文件必须登记**（每条带重构目标），行数只减不增；新出现的超限文件未登记即失败。旧站这条门禁没进 CI，结果 `repo.rs` 5044 行、`pages_posts.rs` 2031 行长期挂账 —— 这次它必须在 CI 里。
- `scripts/check-budget.mjs`：解析 `dist` 产物，gzip 后逐项比对上面这张表，超限失败。
- `pnpm check` 串起：typecheck → lint → test → gate:size → build → gate:budget。

### 9.3 现在不做的性能优化

- 不引虚拟列表（列表超过 200 条再说）。
- 不做图片懒加载以外的优化（不引图片 CDN、不做响应式图）。
- 不做 service worker / PWA。
- 不预取「用户可能要看的下一页」。

## 10. 构建、开发与部署

### 10.1 开发

    pnpm dev        # Vite dev server（默认 5173），/api 代理到后端 8080

- 代理配置写在 `vite.config.ts`，**同域**，因此开发期也不需要 CORS（与生产形态一致，避免「开发能跑生产不行」）。
- 后端本地起：`forum run -config configs/config.yaml`（后端方案 §5.4）。
- **禁止**在开发里用 mock 数据绕过接口：接口没做好就先等，或者在后端加 fake 实现（后端 §12.1 就是这种模式）。理由：旧站的「前端零改动复用」承诺就是被假数据毁掉的。

### 10.2 构建与部署

> dev/prod 双实例、制品、部署脚本与「先出图再交付」的规矩见 `完全重构/部署与开发流程.md`。前端只依赖一件事：**运行期 base**（Vite `base: './'` + Go 注入前缀），所以一次构建能同时跑在 `/` 与 `/dev/`。

    pnpm build      # 产出 web/dist（index.html + assets/[name]-[hash].js|css）

- nginx：
  - `/assets/` → 直接托管 `web/dist/assets`，`Cache-Control: public, max-age=31536000, immutable`（文件名带内容哈希）。
  - 其它 HTML 文档请求 → 反向代理到 Go（由 Go 出带 meta 的 shell）。
  - `/api/` → Go。
- 部署顺序：`pnpm build` → 上传 dist → 重启后端（Go 启动时校验 dist 存在）→ 自检（请求首页 + 一个帖子页，断言 title 非空、`/_assets` 200）。
- **禁止**「本地构建 + scp 到服务器再在服务器编译」这种跨机接力（旧站根因 10）。产物由 CI 产出，带版本号，部署前自检。
- 静态产物**运行期从磁盘读**，不嵌二进制（见 §2.4）。

## 13. 开发规范与禁止清单

### 13.1 规范

- TypeScript `strict: true`；**禁止 `any`**（确实未知用 `unknown` + zod 解析）。
- **只允许 `.ts` / `.tsx`**：不允许出现 `.js` / `.jsx` / `.mjs` / `.cjs`（配置文件也是 TS：`vite.config.ts`、`eslint.config.ts`；门禁脚本是 `scripts/*.ts`，由 Node 24 原生跑 TS）。
- 组件文件 kebab-case，导出的组件 PascalCase；一个文件一个主要导出。
- 注释只写「为什么」，不写「这行在做什么」。
- 每个 feature 的 `api.ts` 只声明端点函数（URL + 入参出参类型），不写业务分支。

### 13.2 禁止（每条都能被检查，逐条来自旧站教训）

| # | 禁止 | 为什么（旧站证据） |
|---|---|---|
| 1 | 在 `lib/api/client.ts` 之外出现 `fetch(` | 旧站有 5 个模块私带 fetch，契约手抄多份 → 422 反复出现 |
| 2 | 手写 URL 或响应字段名 | 同上；路径前缀曾在模板与脚本里散落多处 |
| 3 | 同一份规则/查询实现两遍 | 旧站同一 SELECT 3 份、计数子查询各 4 份 |
| 4 | 组件里写 `alert()` / `confirm()` / `console.log` 留提交 | 用统一 toast 与错误边界 |
| 5 | 组件里读 `window.location` 自己 parse 查询串 | 用路由的 searchParams（也是换渲染模式的前提） |
| 6 | 在 JSX 里写内联 `<style>` 或 `style={{color:'#fff'}}` 定颜色 | 颜色只能来自令牌；旧站样式分散在模板内联与 3 个 CSS 文件里打架 |
| 7 | 用 `dangerouslySetInnerHTML`（`ui/markdown.tsx` 除外） | 清洗只在后端一次 |
| 8 | 把权限判断当安全边界 | 前端只是显示层（后端 §9.8 才是判定层） |
| 9 | 引状态管理库 / 第二套 UI 库 / CSS-in-JS | 见 §3 的「不引入」表；控件基座只有 Ring UI |
| 10 | 组件文件超过 500 行不登记 | 旧站 `pages_posts.rs` 2031 行的前端翻版 |
| 11 | 在测试里 mock 被测组件自身 | 门禁与测试都要能真的红 |
| 12 | 为了「以后可能」预留 props / 抽象层 | 后端方案 §14.1 同款规矩 |
| 13 | 新增 `.js` / `.jsx` 文件 | **约定：只允许 `.ts` / `.tsx`**（含配置与脚本，见 §13.1） |
