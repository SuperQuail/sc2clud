# 施工计划（唯一排期来源）

> 本文档**取代**后端方案 §17 的里程碑排序与前端方案 §12 的 F0–F6 排序——那两章只保留各自的**验收细节**，排期、顺序、并行、上线一律看这里。
> 规矩同其它文档：「必须 / 禁止」是硬性要求。

---

## 0. 施工原则（违反即打回）

1. **一次只推进一步**：每一步有可执行的验收命令或检查项；上一步不过，不进下一步。
2. **一步一个写作用域**：并行的前提是**不碰同一批文件**。同一目录同一时间只有一个施工者。
3. **文档先于代码**：要改行为，先改设计文档（后端 / 数据库 / 前端三份之一），再改代码。
4. **接口未就绪时，在后端加 fake 实现，禁止前端用 mock 数据**（旧站就是被假数据毁掉的）。
5. **旧站继续对外服务**，新站先在预发布地址跑通；切换是**一次性事件**，不是长期状态。
6. **旧数据只迁移一次**，必须先 dry-run 到临时库，核对计数后再正式执行。
7. **每一步都要能回滚**：代码回滚看提交，数据回滚靠切换前的 pg_dump 快照。

## 1. 关键路径

    PG 实例 → S0 骨架 → S1 全部表结构 + 认证 → S2 用户迁移(dry-run) → S3 论坛核心 → S4 图片
      → S5 通知社交 → S6 私信/头衔/issue → S7 邮件/赞赏/下载/搜索 → S8 切换上线

前端 F0 已完成，从 **S1** 起与后端并行；前端只依赖后端方案 §21 的接口契约，不等后端写完。

| 项 | 内容 |
|---|---|
| 交付 | ① migrations/postgres/ 全部表（含 pg_trgm 扩展、生成列、部分索引、CHECK、lower() 唯一索引——**这些 ent 生成不了，必须手写**）；② 认证：注册 / 登录 / 登出 / GET me / 改密码 / 会话管理 / 邮箱验证令牌；③ argon2 并发信号量；④ RBAC（常量 + 角色权限迁移数据 + authz.Require + Perm 中间件 + create-admin）；⑤ CSRF Origin 校验、限流（memlimit）、验证码（默认 off）；⑥ 三根状态轴判定（banned / 未验证 / 未激活） |

| 依赖 | S0 |
| 人日 | 4 |
| 并行 | 2：① 迁移与 schema + 自检脚本；② 认证与 RBAC（两者只在 migrations/ 与 internal/auth/ 交界，约定表名后各写各的） |

## 3. 并行策略（怎么派活）

| 阶段 | 可同时开工 | 写作用域（不得重叠） |
|---|---|---|
| S1 | 后端×2 + 前端×1 | migrations/ + internal/ent/schema/ ｜ internal/auth/ + internal/user/ + internal/authz/ ｜ web/src/** |
| S3 | 后端×2 + 前端×1 | internal/forum/ 读路径 ｜ internal/forum/ 写路径（同包内按文件切，或干脆串行） ｜ web/src/** |
| S6 | 后端×2 | internal/message/ ｜ internal/title/ + issue 相关文件 |
| S7 | 后端×3 | platform/mail/ + notify/ ｜ reward/ + release/ ｜ platform/search/ + backup |

**规则**：每个施工者一个写作用域；跨作用域的改动（例如加一列）由**该列所属模块的施工者**做，别人只调用。前端始终是独立作用域（web/），只依赖 §21 契约。

## 4. 完成定义（DoD，每步都要过）

1. gofmt -l . 无输出、go vet ./...、golangci-lint run（后端）；pnpm check（前端）。
2. go test ./... / pnpm test 全绿；**新逻辑有测试**（尤其事务、权限、金额、状态机）。
3. 数据库文档 §12 的 11 条自检在 CI 里跑，全过。
4. 该步涉及的文档已更新（行为变了就改设计文档）。
5. 提交信息写清「哪一步 + 验收命令」。

## 5. 切换检查单（S8 逐项打勾）

- [ ] 旧库快照 + 旧站数据目录快照已备份到站外
- [ ] forum import-users **dry-run** 报告已核对（用户数、冲突、需重置口令、头像数）
- [ ] 正式导入完成，import_map 行数与旧库用户数一致
- [ ] 抽 5 个真实账号用旧密码登录成功，其中 1 个触发密码重算
- [ ] 抽 3 个头像、1 个头衔、1 个等级在页面上正确显示

- [ ] nginx：/assets/ 长缓存、HTML 交给 Go、/_img/ internal、请求体上限
- [ ] 备份 cron 已生效，且**试恢复过一次**
- [ ] 回滚方案演练：把入口切回旧站，旧站仍能正常读写
- [ ] 切换后 24 小时内**不退**旧站，保留 7 天回滚窗口

## 6. 风险登记

| 风险 | 影响 | 应对 |
|---|---|---|
| 开发机没有 PostgreSQL（本机无 PG、Docker 守护进程未运行） | S0 卡住 | 用 embedded-postgres 起本地实例（数据库文档 §9）；生产机单独装 PG |
| 旧站「邮箱是否验证过」判不出来 | 一批人登录后被要求验证 | 按 email_codes 已消费记录判定；判不出来一律要求验证，并在切换公告里说明 |
| 旧 blobs 的 mime 与真实字节不符 | 迁移后头像裂图 | 迁移时按魔数重新嗅探，不信旧 mime 列 |
| Ring UI 聚合样式 30 KB 顶穿 CSS 预算 | 前端门禁红 | 已把预算提到 40 KB 并写明原因；要更小只能改按需拼 CSS（变量完整性未验证） |
| 切换当天旧站仍有人在写 | 迁移数据落后 | 流程写成：旧站置只读 → 最后一次增量导入 → 切入口；或接受窗口内少量丢失并在公告说明 |
| 施工者不熟三份文档 | 各写各的 | 开工前把对应章节链接贴进任务描述；DoD 第 4 条强制更新文档 |

## 7. 可以砍的（时间紧时按此顺序砍）

1. **私信**（S6 的一半）：改回 v1 不做，等论坛跑起来再加。
2. **头衔与等级**（S6 的另一半）：数据照迁，功能后置。
3. **资源帖 issue**（S6）：独立功能，可整块后置。
4. **搜索**（S7）：先用标题 LIKE 顶一下，tsvector 后置。
5. **公告横幅**（S5）：首页少一个条幅不至于不能用。

砍掉的都要在文档里写明「已定案：不做」，**不是悄悄不写**。
