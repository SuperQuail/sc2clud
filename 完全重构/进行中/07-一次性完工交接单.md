## 3. 工作协议（**每一小步都做，不许攒**）

**这条是为「你中途因 API 波动挂掉、下一个接手」定的：你的对话不会传给谁，只有仓库会。**

1. 一完成一小步就 `git commit`，**只 `git add` 你改的文件**（工作区可能有别人的在途文件，**绝不 `git add -A`**）。
2. **同一个 commit 里更新你的进度文件** `完全重构/进行中/进度-<你的包>.md`，固定四行：
   ```
   - [x] 这一步做了什么

     - 下一步：<文件 + 函数 + 改成什么>   ← 接手的人照着这句就能继续
   ```

## 5. 已知陷阱（都踩过，别重踩）

1. **契约两侧各写一份，各自的测试都过** —— 这是本仓库最高频的事故。已发生：激活码 `{token}` vs
   `{username|email, code}`（激活 100% 400 且界面显示成"验证码不对"）、重置密码 `token` vs `reset_ticket`、
   评论 `viewer.value` vs `my_vote`（赞踩态恒假）、举报行 `target_title` vs `target_label`（每行标题恒空白）、
   `sort=hot`（后端必 400）、`ai_review_note` 列根本不存在（**编辑正文必然 500**）。
   → **写任何字段前先去 `forum/internal/**` 的 DTO 里看一眼**。
2. **"接口 200、界面看着正常、其实什么都没发生"** 是主要缺陷形态；同样地，"端点声称做到的事没做到"
   （人工放行不还原 `visibility` → 通过了却全站不可见）只能靠**独立的人按契约证伪**才抓得到。
3. **永远通过的检查比没有检查更糟**：`npx rg` 在这台机器上会拉一个同名脚手架包、**退出码 0 无输出**；
   `Select-String` 传目录**不递归**。要证明"0 命中"，必须自己列文件、并且**先用已知有问题的输入验证它会红**。
4. **出图不等于验过**：图可能拍的是旧产物、或一张 Vite 报错浮层（曾出现一批字节数完全相同的图）。
   出图时往 DOM 插一个**可见标记**，从图里读得到，才证明拍的是当前源码。
5. **假时钟**：测试台 `clock.Fake` 的时间**不前进**，任何用时间戳当版本号的逻辑在用例里都会"看不出变化"
   （`updated_at` 守卫就是这么差点测不出来的）——必要时先 `h.clk.T = h.clk.T.Add(...)`。
6. **组件同名撞车**：`lib/api/social.ts` 的类型 `NoticeSettings` 与 `@/ui/message/notice-settings` 的组件同名，
   改一处会撞另一处的编译。import 时起别名。
7. **`fs` 报文件被占用/被改过时不要用 shell 就地写**（会写出半截文件，没有版本保护）。
8. **并发**：`pnpm check` 会 `pnpm build` 清空 `dist/`；`deploy/.stage` 是固定路径。
9. `web/src/devroom/registry.ts` 是"控件白名单"的唯一真源；新增控件要**先在 DevRoom 出一页验证 → 登记 → 才能用**。

1. `cd web && pnpm check` **全绿**（贴结尾输出，不接受"已通过"三个字）；
2. `cd forum && gofmt -l . && go vet ./... && go test ./...` **全过**（用第 1 节的 Go 路径与环境变量）；
3. 改过的每一页**出图并看图**（含非默认态：空/错误/未登录/窄屏）；
4. 任务清单里每一条都在**同一个 commit 的进度文件**里留了「证据 + 下一步」；
5. 新增的每条机器检查，都证明过它**会红**。

## 7. 明确不在范围

- 旧站 `site/` 的任何实现（正是要扔掉的东西）；
- 引入新依赖（除非像 §"依赖与实现"那条一样能显著减少自己要负责的正确性面，并在 commit 里写清换掉了什么）；
- `deploy/**` 与生产切换（由 Lead 串行做）；
- 未列入第 4 节的"顺手优化"。
