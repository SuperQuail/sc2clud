## P0 · 会伤数据（必须先修）

### D1 `posts` 的幂等键没有唯一索引 —— 重放会重复插楼

- **现象**：同一个发帖请求重放（或 seed 跑第二遍），楼层重复。实测：`seed` 第二遍 `topics` 不变但 **`posts` 从 106 涨到 181（+75）**，库里 75 组 `client_token` 各两行。
- **根因**：`migrations/postgres/0004_forum.up.sql:145` 建的是 `CREATE INDEX idx_posts_author_client_token`（**普通索引**），
  而 ent schema `post.go:22` 与 d3 设计承诺的是**部分唯一索引** `uq_posts_author_client_token`。
  `CreatePost` 的幂等**完全押在那条索引上**（靠 23505 回查既有行）—— 索引不在，**那个回查分支是死代码**。
  同一批里 `topics` / `post_issues` 的同类索引都是 UNIQUE，**只有 posts 写错**（照着旁边抄没抄对）。
- **修法**：① 一条新迁移：先清理重复行、把索引改成**部分唯一索引**；
  ② **加一条「uq_* 索引存在且唯一」的启动自检** —— 现在只有「外键索引自检」，没有「设计承诺的索引是否存在」，
  所以它才能静静地错到今天；③ 一条会红的用例：同一 token 建两次 → 只有一行。
- 发现者：seed 施工者。**未修。**

## P1 · 挡住用户看内容

### D2 帖子详情页评论区**一条都不渲染**

- **现象**：`/dev/t/<uuid>` 写「评论 6」，列表 0 条，DOM 容器 `innerHTML.length === 0`；接口 200 且返回 6 条楼层。
- **根因**：**契约两侧各写了一份约定** —— 后端 `parent_id` 顶层发**空串**（`dto.go:118` 注释「空串 = 顶层」，`map.go` 用 `deref()` 把 NULL 变空串），
  前端声明 `string | null`（`web/src/lib/api/forum.ts:98`）并按 `=== null` 过滤（`routes/_parts/mappers.ts:43`）→ roots 恒为空。
  **同一接口还根本没下发楼中楼的父 id**：库里 floor 3 的 `parent_id=100035`，API 给的是 `""`。
  `IssueCommentDTO.ParentID`（`dto.go:186`）同写法 → issues 评论同病。
- **为什么测试没抓到**：Go 侧断言字段是空串、前端 mock 写的是 `null` —— **两边各自的测试都过，序列化那一层没人测**。
- **修法**：`dto.go` 两处 `ParentID string` → `*string`（顶层 `null`、楼中楼发**父的 public_id**，前端才能真正归并楼中楼）；
  **加一条接口级断言**：有楼中楼的帖子，响应里至少有一条 `parent_id` 非空。
- 发现者：**两个 agent 独立发现**（迁移 + seed）→ 高置信。**未修。**

### D3 个人主页：端点没注册 + 响应形状不符

- **现象**：个人主页统计三格全是「—」，「最近发布」永远停在「正在加载帖子…」。
- **根因**：前端调 `GET /users/{handle}/topics`，而 `forum.ListUserTopics` **有实现、没有路由**；
  且前端要 `stats{topic_count, reply_count, like_received}` 与 `is_self`，后端给的是扁平 `topic_count`。
- **修法**：注册路由 + 响应按前端契约补 `stats{}`/`is_self`；**再加一条机器检查**：
  「前端 `api/*.ts` 里出现的每个路径都能在后端路由表里找到」（这类缺口现在靠人对）。
- 发现者：seed 施工者。**未修。**

### D4 迁移进来的老帖**搜不到**，而且没有重建入口

- **现象**：`topic_search` 里老帖 0 行（实测搜「弥音」→ 0 条）；seed 的主题有 25 行。
- **根因**：迁移走原生 SQL，绕过了 `CreateTopic` 会做的 `search:index` 入队；而 `topic_search` 是**派生表、没有任何重建入口**。
- **修法**：做一个幂等的 `forum reindex`（只重建缺失/过期的行）+ 迁移文档写明「导入后必须跑一次」；
  再加一条自检：`topic_search` 行数 != 可见主题数就报警。
- 发现者：seed 施工者。**未修。**

## P2 · 会让人误判（「200 其实不是我们的站」那一族）

### D5 不存在的 `/api/v1/*` 路径返回 **200 + SPA HTML**

- **现象**：`GET /dev/api/v1/users/x/topics`（未注册）→ **200**，body 是 `index.html`；`/api/v1/search?q=…` 同样。
- **根因**：Go 壳的 NoRoute 兜底对所有路径一视同仁返回 SPA，**API 前缀没有自己的 404**。
- **修法**：`/api/` 前缀下未命中 → **404 JSON**（app 层一行守卫）。
- **危害**：客户端拿到 200 会当成「成功但空」，与「功能不存在」无法区分 —— 这正是本项目反复栽的那一类。
- 发现者：seed 施工者。**未修。**

## P3 · 迁移造成/暴露的，需要决定

### D6 公告区「只有管理员能发帖」在迁移后消失
老 `sections` 有发帖/回帖**两档门槛**，新站只有**一个** `min_post_level`；本次 6 个分区全映射成 0 → 约束丢失。
**要么**在 `boards` 上加回一档（回帖门槛），**要么**接受「新站只有一档」并在文档里写明。**需要产品决定。**

### D7 `todayStart()` 硬编码 UTC+8
`forum/pgsql/topics.go` 里「今日 X 帖」用硬编码 UTC+8 —— 换时区或跨零点会对不上。

### D8 老站的 13 个 `site_texts` 键全部丢弃
新站 `SettingSpecs` 是唯一真源，没有这些开关 —— **等于把老站的 AI 审核与邮件节流配置整块留在了旧站**。要有对应功能才能迁。

### D9 老口令能不能登录：静态分析能，**没实测**
老库是 argon2id PHC、新站 verifier 从串里读参数 → 能登，登录后按新参数 rehash。没有明文口令可试。

## 环境问题（会直接挡住下一个部署）

1. **C 盘只剩 0.04GB** —— 第一次部署死在 `WriteAllBytes: not enough space`。
   根因：`%TEMP%\forum-pg-*` 积了 **698 个 embedded-postgres 数据目录 / 66GB**（testsupport 的 TestMain 在进程被杀时不清理）。
   已清过一次（回到 64GB），但**根因没修** → 会再积。
2. **`deploy/.stage` 是固定路径，两个部署不能同时跑** —— 并发时一个会把另一个的 stage 删掉（实测发生过）。
3. **`/tmp` 下有 6 个含 `PGPASSWORD` 的脚本**（施工者临时产物）——临时目录重启即清，但「口令出现在 /tmp 脚本里」值得记一条。
4. **`/tmp/wipe.sh` 已删** —— 它会 `DELETE FROM users WHERE username <> 'probe_x5'` 清空库，且 `AND/OR` 优先级写错（实测 `audit_logs` 被清零）。
