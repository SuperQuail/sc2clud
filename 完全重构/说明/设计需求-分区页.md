# 设计需求：分区页（Board 页）

> 2026-10-12 需求。**只给需求与结构，不给版式**——版式由设计者定，出三份以上不同的真实渲染图由人挑（见 开发必读 §8）。

## A. 分区（参考百度贴吧的「吧」页**结构**，不抄视觉）

| 承载 | 说明 |
|---|---|
| 分区身份 | 名称、一句话简介、封面/图标 |
| 分区统计 | 主题数、回复数、今日新帖、成员/关注数 |
| 分区操作 | 关注 / 取消关注、发帖入口、分区内搜索 |
| 分区内导航 | 一横排标签（全部 / 精华 / 资源 / 讨论 / 公告…），必须有「当前选中」表达 |
| 分区切换 | 能跳到别的分区（左栏列表 / 顶部下拉 / 二级栏都行） |

## B. 帖子列表：**两种视图都要做，且能切换**

### B1 卡片视图（硬指标：**一屏 ≥4 张**）

测量口径：**1440×900 的可视区**，扣掉顶栏与分区头之后，完整可见的卡片 ≥4 张。
卡片承载：封面（可无）、类型徽标、标题、摘要、作者+头像、回复/点赞/浏览数、最后回复时间、置顶/精华标记。

### B2 紧凑列表视图（参考 Discord 消息列表）

- 头像在左；名字与时间同一行；标题/内容紧随；
- **行与行之间没有边框分割**，靠行距与 hover 底色区分；
- 节奏紧、一屏尽可能多条；置顶/精华用左侧细条或小标记，**不要大色块**；
- 元信息（回复/赞/浏览）弱化，不要每行都堆成表格。

### B3 切换

卡片 ⇄ 紧凑的切换控件，位置与形态自定；**切换状态要进 URL**（如 `?view=card|compact`），可分享、可后退。

## C. 状态与响应式（两视图共用）

- 骨架 / 空 / 错误 三态；游标分页「加载更多」，到底换文案；
- 三档：<768 单列；768–1199；≥1200（贴吧式常驻左栏只在这一档出现）；
- 深浅色两套（`html[data-theme="dark"]`）。

## D. 数据字段（假数据自己造，字段名照这个，与后端 §21 契约一致）

    分区: name, slug, description, cover, topic_count, post_count, member_count, today_count, joined
    主题: id, title, excerpt, kind(discussion|resource|repost), author{handle,nickname,avatar},
          reply_count, like_count, view_count, last_reply_at, created_at, cover?, pinned?, featured?

## E. 硬约束（违反即返工）

1. 只允许 `.ts`/`.tsx`；不引入新依赖；
2. **不允许手写 HTML 控件**（`<button>/<input>/<select>/<textarea>/<table>/<dialog>`）——用 Ring UI，或先封装成组件再复用（并行做变体时封装在各自目录里，标注「待提升为 src/ui」）；
3. 颜色与间距只用 `src/styles/tokens.css` 的令牌；容器作用域内可覆盖取值，不得改全局令牌；
4. 图标只用 lucide-react；禁止 fetch（本地假数据）；
5. 收工必须 `cd web && pnpm check` 通过，并贴出结尾输出。
