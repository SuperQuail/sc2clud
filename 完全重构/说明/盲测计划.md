# 盲测计划（用户 2026-10-13 定）

> 目的：**找出我们忘了的东西**，不是验证我们写了的东西。
> 所以两个 agent 的分工是刻意不对称的：一个**不许给明确任务**，一个**只给明确的核心任务**。

## 一号盲测：模糊探路（**不给定明确任务**）

给 agent 的只有一句话级别的目标——「你是这个站的新用户/管理员，随便用，把用不了、看不懂、缺东西的地方记下来」，
**不给功能清单、不给验收标准、不给流程**。

为什么必须模糊：给了清单就变成「按清单点一遍」，而清单是我们写的——**我们忘掉的东西不会出现在清单里**。
目标形态（照抄给 agent）：

> 你是一个刚听说这个站的人。站点在 http://127.0.0.1:8080。
> 你会想做什么就做什么，想点哪里就点哪里，想注册就注册、想发帖就发帖、想改设置就改设置。
> **不要先读设计文档**（那是出题人的答案）。
> 把你**做不成的事、看不懂的地方、以为有却没有的东西**逐条记下来，每条写清：你想做什么、实际发生了什么。
> 最后再去做一件事：**把你觉得「一个论坛应该有的」列出来，然后对照这个站，逐条标有没有。**

允许它乱点（那正是目的）；要求它**每条都复现一次**（避免误报）。

## 二号盲测：死磕核心功能（**指定明确的重要任务**）

只给一份**功能清单**（明确到「做什么、期望什么」），要求它逐条执行并给出通过/失败与证据。
重点就是**发帖这条主链路**——它是这个站的命，断了网站就没意义。

给 agent 的清单（照抄）：

    注册 → 收验证码 → 激活 → 登录 → 发一篇带图的帖子 → 看到它出现在列表 → 点进详情 → 回复 →
    给回复点赞 → 举报一条 → 被举报内容出现在管理队列 → 管理员审核通过/驳回 → 作者看到审核结果 →
    编辑自己的帖子 → 删自己的回复 → 管理员封号 → 被封者立刻 401（不能等 60 秒）→ 解封 → 改密码 →
    旧会话立刻失效 → 上传头像（≤64KB）→ 换主题深浅色 → 退出登录

每条要求给出：**命令或操作 + 实际响应 + 通过/失败**。失败要区分「功能没做」与「做了但不对」。

## 两个 agent 的共同纪律

1. **不许改任何代码**（只读 + 只用 HTTP/浏览器）。发现问题写报告，不动手。
2. **每条结论都要有证据**（请求与响应的原文、截图、或命令输出）。**不接受「感觉不对」**。
3. **区分三类**：① 功能没做；② 做了但行为不对；③ 做了也对，但界面上找不到入口（这一类最容易被忽略，也最伤用户）。
4. 报告按「**挡住上线 / 影响使用 / 体验问题**」分档，每条一句话说清影响。

## 前置条件（缺了盲测没意义）

- [ ] P2 五个域交付、app 层接线完成；
- [ ] 全仓 `gofmt / vet / build / test` 四连绿；
- [ ] `forum migrate` 在空库跑通、`forum create-admin` 能建出第一个管理员；
- [ ] `forum run` 起得来，前端产物在它旁边（`web/dist`）；
- [ ] 有一个能收验证码的邮箱账号（或把验证邮件改成写日志/写文件，**盲测专用**）；
- [ ] 管理员账号与测试用户账号各一个。

> 验证码这一条是盲测的真实阻塞点：没有可收信的邮箱，注册链路根本走不完。
> 方案（二选一）：① 配一个真实 SMTP（有额度的话）；② **dev 档把验证邮件写进日志/文件**（`mail.driver=log`），盲测从日志里读 6 位码。
> 我倾向 ②：它让「注册 → 激活」这条链在没有任何外部依赖的情况下可测，而且**代码里本来就需要一个离线可验证的发信实现**（值得加，不是为盲测临时造的）。
