> 2026-10-12。这是**唯一**记录服务器上有什么、密钥在哪、怎么自检的地方；**改服务器前先看这份**。

## 1. 硬件与系统

    Ubuntu 22.04.5 LTS / 内核 5.15 / 2 核 / 3911 MB / 根盘 97G（已用 20G）
    swap 8GB（单个 /swapfile，已写入 fstab）
    vm.swappiness=10   vm.overcommit_memory=1（Redis 要求）

**swap 是兜底不是容量**：8GB 用来吸收突发（pg_dump/恢复、图片批处理、Go GC 尖峰），目标仍是「常驻不换出」。

## 4. Redis 配置（已生效）

    bind 127.0.0.1        ← 不要写 '-::1'，那是 Redis 7 语法
    requirepass <64 hex>  supervised systemd   daemonize no
    maxmemory 256mb       maxmemory-policy allkeys-lru
    save ""               appendonly no        ← 纯缓存，不落盘（避免 fork 内存尖峰）

**两个已踩的坑**：① `bind 127.0.0.1 -::1` 在 6.0 会被当成主机名 → 启动失败；② systemd 下不设 `supervised systemd` + `daemonize no` 会反复重启。

## 6.1 改完 fstab 必须这样验证（不是看一眼就算）

    # 全部下线，再只靠 fstab 拉起来——能拉回来才算数
    swapoff -a && swapon -a && swapon --show
    findmnt --verify --verbose     # 0 parse errors 才算合法（swapfile 那条 warning 是正常的）
    systemctl daemon-reload        # 清掉旧的生成单元（例如删掉 /www/swap 后的残留）

已实测（2026-10-12）：swapoff -a 后 swap 归零，swapon -a 后 8G 恢复，/swapfile 权限 600 root:root。

## 7. 运维纪律（都是踩过才写的）

1. **服务器操作一律「本地写脚本 → scp → 执行」**，不要用 ssh 内联命令——PowerShell → ssh → 远端 shell 三层引号会静默吃掉命令（`sqlite3 .backup` 就这么失败过一次）。
2. **改配置先备份**，备份放到 `/root/old-dev-backup/`（不在仓库、不在 /srv）。
3. **归档必须有独立校验**（sha256 + 本地真开库），否则等于没做。
4. **nginx vhost 不手改**：以后由部署脚本生成；当前这份是旧站留下的，含 `sc2clud_app` / `sc2clud_dev` 两个 upstream。
5. **磁盘**：已清掉 Rust 工具链 950M（项目改用 Go），这台机器不该再出现 `cargo`/`rustup`。
6. **swap 不是容量**：靠 swap 撑住的进程会让整机变慢，`MemoryMax` / `GOMEMLIMIT` 该设还得设。
