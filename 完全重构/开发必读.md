# 开发必读（开工前 3 分钟看完，写完必须能过）

> **这是所有开发（人类与 AI 子 agent 都一样）的第一份文档。**
> 子 agent 的派发提示里必须原样包含本文的「§1 硬规则」与「§5 收工条件」两块，**不允许只说「去看文档」**——实测那样等于没说。

## 1. 硬规则（违反即返工，全部有机器检查）

| # | 规则 | 检查在哪 |
|---|---|---|
| 1 | **不允许在 HTML 里自己实现控件**。`<button>` / `<input>` / `<select>` / `<textarea>` / `<table>` / `<dialog>` 一律不许直接写 | `pnpm gate:ui`（告警）+ ESLint（挡住） |
| 2 | **需要新控件时，先做成库里的控件**：加到 `web/src/ui/`，写清 props 与可访问性，再从那里引用。**不允许**就地写一次性的 HTML | 同上；评审看 `src/ui/` |
| 3 | 控件优先用 **Ring UI**（`@jetbrains/ring-ui-built`）；Ring UI 没有的，才在 `src/ui/` 用 shadcn 风格自建 | 同上 |
| 4 | 只允许 `.ts` / `.tsx`，禁止 `.js` / `.jsx` / `.mjs` | ESLint + 目录扫描 |
| 5 | 颜色/间距只能用 `src/styles/tokens.css` 的令牌，不写死色值 | 评审 + `gate:ui` 可扩展 |
| 6 | 只允许在 `src/lib/api/client.ts` 里 `fetch` | ESLint `no-restricted-globals` |
| 7 | 不引入新依赖；不用第二套同类控件库 | 依赖 diff 评审 |
| 8 | 后端：所有读写走 ent；原生 SQL 只允许在 `platform/search/pgsql` 与手写迁移里 | 评审 + golangci-lint |

## 2. 我要写个按钮/输入框，正确做法是什么

    // ❌ 错：就地写 HTML
    <button className="px-4 py-2 bg-primary">发帖</button>

    // ✅ 对：用 Ring UI（首选）
    import Button from '@jetbrains/ring-ui-built/components/button/button';
    <Button primary>发帖</Button>

    // ✅ 对：Ring UI 没有的（例如业务专用组合控件）→ 先加进库里
    //   web/src/ui/topic-actions.tsx  （在库里写一次，写清 props 与 aria）
    //   然后各处 import { TopicActions } from '@/ui/topic-actions';

**判断标准**：如果这段 HTML 你写了第二遍，它就该是 `src/ui/` 里的控件。

## 3. 目录与归属（写之前先看这一行）

| 我要写的东西 | 放哪 |
|---|---|
| 基础控件（按钮/输入/下拉/弹窗/标签） | `web/src/ui/`（优先直接用 Ring UI，不重复造） |
| 业务域数据逻辑（接口 + query key + 组合） | `web/src/features/<域>/` |
| 页面（组装 feature + 布局） | `web/src/routes/` |
| 后端业务 | `forum/internal/<模块>/`，分层与依赖规则见后端方案 §4 |
| 数据库表结构 | 只改 `forum/internal/ent/schema/` + 手写迁移 |

## 4. 只看这三份，别翻别的

1. `完全重构/开发必读.md`（本文）；
2. 你那块的设计文档：`数据库设计-postgresql.md` / `论坛后端技术方案-v2.md` / `前端架构设计-v1.md` / `性能与容量.md`；
3. 服务器相关再读 `服务器清单与运维.md` 与 `部署与开发流程.md`。

**旧站 `site/` 一律不许参考**——它的实现方式正是我们要扔掉的东西。

## 5. 收工条件（缺一条不算完成）

    cd web && pnpm check        # typecheck → lint → 控件告警 → 测试 → 体量门禁 → build → 体积门禁
    cd forum && gofmt -l . && go vet ./... && go test ./...

并在回报里**贴出命令与输出**（不是「已通过」三个字）：

- 改了哪些文件；
- `pnpm check` 的结尾几行；
- 你新增/复用了哪个 `src/ui/` 控件；
- 你不确定的地方（写出来，别猜）。

## 6. 为什么有这份文档

旧站的失败清单里有一条：**规则写在文档里、没有机器检查，于是没人执行**（复盘根因 11）。
所以本仓库的约定都遵守同一条原则：**每条「必须」都要有落点**——要么有检查命令，要么在收工条件里逐条核对。给不出检查方式的规则，不写进文档。
## 7. 给子 agent 的派发模板（Lead 派活时必须原样带上）

**原因**：实测子 agent 不会主动翻文档；只说「去看 完全重构/」等于没说。派发提示里必须**内联**下面两块，并**要求交回命令输出**。

    【开工前必读，照做】
    1. 先读 完全重构/开发必读.md（本文的对外版，含硬规则与目录归属）；
    2. 再读与你这块相关的设计文档（数据库设计 / 后端方案 / 前端架构 / 性能与容量）；
    3. 禁止参考 site/（旧站实现），禁止引入新依赖。

    【硬规则摘要（违反即返工）】
    - 不允许手写 HTML 控件（<button>/<input>/<select>/<textarea>/<table>/<dialog>）；
      需要新控件就先加进 web/src/ui/ 再复用，首选 Ring UI（@jetbrains/ring-ui-built）；
    - 只允许 .ts/.tsx；只用 src/styles/tokens.css 的令牌；fetch 只在 src/lib/api/client.ts；
    - 后端：读写全走 ent，原生 SQL 只在 platform/search/pgsql 与手写迁移里。
