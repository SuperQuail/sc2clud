# 开发必读（开工前 3 分钟看完，写完必须能过）

> **这是所有开发（人类与 AI 子 agent 都一样）的第一份文档。**
> 子 agent 的派发提示里必须原样包含「§1 硬规则」与「§5 收工条件」两块 —— 实测只说「去看文档」等于没说。

## 1. 硬规则（违反即返工，全部有机器检查）

| # | 规则 | 检查在哪 |
|---|---|---|
| 1 | **不允许在 HTML 里自己实现控件**。`<button>` / `<input>` / `<select>` / `<textarea>` / `<table>` / `<dialog>` 一律不许直接写 | `pnpm gate:ui`（告警）+ ESLint（挡住） |
| 2 | **需要新控件时，先做成库里的控件**：加到 `web/src/ui/`，写清 props 与可访问性，再从那里引用。**不允许**就地写一次性的 HTML | 同上；评审看 `src/ui/` |
| 3 | 控件优先用 **Ring UI**（`@jetbrains/ring-ui-built`）；Ring UI 没有的，才在 `src/ui/` 用 shadcn 风格自建 | 同上 |
| 4 | 只允许 `.ts` / `.tsx`，禁止 `.js` / `.jsx` / `.mjs` | ESLint + 目录扫描 |
| 5 | 颜色/间距只能用 `src/styles/tokens.css` 的令牌，不写死色值 | `gate:tokens` |
| 6 | 只允许在 `src/lib/api/client.ts` 里 `fetch` | ESLint `no-restricted-globals` |
| 7 | 不引入新依赖；不用第二套同类控件库 | 依赖 diff 评审 |
| 7.5 | **不许覆盖控件库的样式/尺寸变量**（要改就在 `src/ui/` 包一层，或换库）。令牌只做「引用库变量」的别名 | 评审 + 看 §11 |
| 8 | 后端：所有读写走 ent；原生 SQL 只允许在 `platform/search/pgsql` 与手写迁移里 | 评审 + golangci-lint |

## 2. 我要写个按钮/输入框，正确做法是什么

    // ❌ 错：就地写 HTML　　// ✅ 对：Ring UI 首选
    <button className="px-4 py-2 bg-primary">发帖</button>
    import Button from '@jetbrains/ring-ui-built/components/button/button'; <Button primary>发帖</Button>
    // ✅ 对：Ring UI 没有的（例如业务专用组合控件）→ 先加进 web/src/ui/（写清 props 与 aria），再各处 import。

**判断标准**：这段 HTML 写第二遍，它就该是 `src/ui/` 里的控件。

    cd forum && gofmt -l . && go vet ./... && go test ./...

回报里**贴出命令与输出**（不是「已通过」三个字）：改了哪些文件 · check 结尾几行 · 新增/复用了哪个 `src/ui/` 控件 · 不确定的地方（写出来，别猜）。

## 6. 为什么有这份文档

旧站的失败清单：**规则写在文档里、没有机器检查，于是没人执行**（复盘根因 11）。本仓库同一条原则：每条「必须」都要有落点——要么有检查命令，要么在收工条件里逐条核对。给不出检查方式的规则，写成附录 A 的人执行项并标明。

## 8. 出图（前端改动的交付门槛）

**规矩**：可能影响渲染的改动，**先出真实渲染图再交付**；新页面给 ≥3 份方案由人挑（单一明确改动除外）。工具不用装 Playwright（本机有 Chrome/Edge）：

    cd web && pnpm preview:dev            # http://127.0.0.1:5199/preview.html?s=a|b&v=1|2&theme=light|dark
    node web/scripts/cdp-shot.ts <url> <out.png>   # 支持点击/输入/滚动/CDP_SIZE=390,844（逗号！）；别的脚本见 shots/

**硬要求**：① 真组件真数据渲染（不许贴设计稿）；② 不许空壳（同页面的顶栏/列表/侧栏要在图里）；③ **预览与上线没有第二套代码**；④ 出图前自己看图（塌陷/逐字换行只有看图能发现）；⑤ **证明拍的是当前源码**：页面 DOM 里有可见标记（`MARKER-…`），出图后从图里读到它才算数（假绿的一类：字节数相同的报错浮层、空图、部署换 hash）。

### 8.1 产品页预览入口（`product.html`）

    http://127.0.0.1:5199/product.html?route=/            首页

## 11. DevRoom：没验证过的控件禁止直接用

**规矩**：控件先在 `web/src/devroom/` 验证并登记进 `registry.ts`；没登记就 import → `pnpm gate:controls` 直接失败。
**为什么**：lucide 图标直接塞进 Ring `icon` prop 类型兼容、编译与测试都不报，但 24×24 vs 16px **图标顶高按钮**——只有图能发现。

标准流程：① 在 `devroom/pages/0N-<控件>.tsx` 渲染全部变体（尺寸/图标/禁用/加载/长文本/深浅色），每行写「为什么」；
② `pnpm preview:build && pnpm devroom` 出图**看图**；③ registry 登记实测 props 与坑；④ 业务代码才能 import。

| 门禁 | 管什么 |
|---|---|
| `gate:ui` | 不许手写 HTML 控件 |
| `gate:controls` | 只许用登记过的控件 |
| `gate:size` | 单文件 ≤500 行（超了登记重构目标，行数只减不增） |
| `gate:budget` | 首屏 JS ≤180KB（2026-10-15 起档，归因与改档理由见 `web/scripts/check-budget.ts`） / CSS ≤40KB gzip |
## 12. 路径只能有一个来源（src/lib/url.ts）

    import { appPath, assetUrl } from '@/lib/url';   // 应用内跳转 / public/ 静态资源
    <img src={assetUrl('miyin/wink-520.webp')} />

**不许**在组件里写 `href="/xxx"`、`src="/xxx"`、自己拼资源名；`pnpm gate:urls` 会挡。**注意两个拼法的分工**：
`assetUrl()` 是 `public/art/**` 静态素材；`imagePath('/img/<hash>')` 是图片端点资源 —— 混用就是裂图（D27）。`appPath/imagePath` 一样分工。

**为什么**：同一份产物跑两个前缀（生产 `/`、dev `/dev/`），散落必坏（踩过两次）；前缀来自 `<base href>`（Go 壳按实例注入），`BASE_URL` 构建期常量不用。
## 13. 打包与部署只能走程序

    cd web && node scripts/pack-dev.ts <git-sha>      # 或 pnpm pack:dev <sha>

顺序：产品构建（VITE_DEVROOM=1）→ DevRoom 构建 → 并入 `dist/devroom/` → **产物自洽门禁 `check-bundle.ts`** → Go 交叉编译 → 打包 → 回读 tar 校验。**dev 部署要求 `dist/devroom/index.html` 存在，缺了就拒绝**（deploy.ps1 已内置此守卫；`-SkipBuild` 同样挡）。

| check-bundle 查什么 | 抓的事故 |
|---|---|
| 两入口都在（`dist/index.html`、`dist/devroom/index.html`） | pnpm build 清空 dist，手工塞的 DevRoom 被抹 |
| DevRoom 每个页面 key 都在产物 JS 里 | 新加页没重新构建 → 入口不存在 |
| `public/art/**` 每张图在 `dist/art` 与 `dist/devroom/art` 都在 | 丢一张图 = 一处裂图 |
| （dev 制品）产品侧有 DevRoom 入口 | 生产构建被装到 dev → 首页没有进房间的门 |

**铁律**：`pack-dev.ts` 非 0 退出**绝对不许跑部署**；部署脚本先解临时目录校验、再停服务。这三类事故 typecheck/lint/单测全不报——只在产物层存在，所以必须是门禁。

## A. 人执行项（事故驱动，没有机器检查——所以单列，写短、写可核）

1. **并发**：只杀**自己按端口属主定位**的进程；绝不按进程名群杀（chrome/node/msedge 都不行——机器多人共用）。临时目录各人自己的名字，收工即删。不留痕迹的事故最难查，所以写死。
2. **推断不算验收**：报「改完会怎样」必须区分实测与推算；「因为共用 X 所以 Y 也会变」的推断要在 Y 那里**真的看一眼**（已被实测推翻三处）。改代码必出图的边界：**纯注释与纯类型不用**——图不为此跑流程，才会在真正需要时不麻木。
3. **每个状态分支一条会红的断言**（本人/别人、登录/未登录、空/满/错误），**非默认分支优先**；判对象真值（`!obj`）是典型病：**问它的字段，不是它本身**。默认态的图代表不了其它分支。
4. **截图/出图说谎的识别**：两张图字节数完全相同 = 大概率同一张报错浮层；退出码 0 + 空域（allButtons=0）= 拍的不是你以为的那份。一律以可见 MARKER 兜底。
5. **文案实话**：功能没做用户看得出来，文案骗人会等人等一个不会来的答复 → 把不实文案改成实话并标注，**不为兑现文案发明功能**。
6. **依赖与实现（2026-10-14 拍板）**：「无新依赖」不是优点——判断只看**成熟依赖能否显著减少我们要负责的正确性面**。正例保留：点阵验证码（十几行确定性代码）；反例：手写 OpenAI 兼容调用 → 换 `sashabaranov/go-openai`。
7. **常见功能：要么不做，要么引可靠库（2026-10-15 拍板，覆盖上一条）**——不从零维护规则表：表会随真实世界漂移。**「小到十几行」不豁免**。引依赖时在 commit 里写清**换掉了哪些自己维护的正确性面**。
8. **邮箱去重（2026-10-15 决定）**：不做 Gmail `+tag`/点号折叠。现状已是双层保证（`uq_users_email_lower` 唯一索引 + 注册预检 `ErrEmailTaken`）；第三方校验 API 与验证码机制重复、隐私有代价；将来要做也只有一条路：**引可靠的邮箱归一化库**，不往 `normalizeEmail` 里填域名表。
9. **git 与进程（多 agent 并行约束）**：只准 `git add <明确路径>` + `git commit`；`git reset` / `git stash` / `git checkout --` 只归 Lead——索引会被并发的清理动作冲掉（已发生过）。**Lead 在跑时不要部署**（构建会带走在途半成品）。**出图脚本也在 tsconfig 下**：改 `scripts/*.ts` 必须过 tsc，否则一条工具错会卡死 `pnpm build` 与部署链。
