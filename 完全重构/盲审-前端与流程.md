## F01 | blocker | 前端架构设计-v1.md:66,455 · 部署与开发流程.md:28 · web/vite.config.ts:6-13 · web/dist/index.html:25-26

- **问题**：支撑整个"一次构建、跑在 `/` 与 `/dev/`"的运行期 base 三条腿一条都没实现：`window.__BASE__` 在 `web/` 全目录 0 处出现（grep 实测，只出现在两份文档里）；`vite.config.ts` 没有 `base` 选项（默认 `/`）；产物 HTML 引用的是绝对路径 `/assets/index-*.js|css`；`client.ts:4` 硬编码 `/api/v1`；`router.tsx:10` 的 `createBrowserRouter` 无 basename。
- **为什么是问题**：这是部署设计的地基（"不再有 sub_filter"）。现状下 `/dev/` 的 HTML 仍然去请求 `/assets/*`，而 nginx 的 `/assets/` 只可能指向一个目录 —— 两个实例中必有一个加载到**另一个实例的前端产物**，或直接 404，正是文档声称已经消灭的"新面板全 404"（根因 10）。若改成 `base: './'` 而不做 `<base href>`，深链接 `/dev/t/:id` 会把 assets 解析成 `/dev/t/assets/…`，同样 404。三个前缀（Router basename / API 前缀 / 资源路径）当前是三种各自硬编码的写法，没有单一真源。
- **最小修法**：拍板一种：Go 壳在返回 HTML 时同时注入 `window.__BASE__` 并按它重写 `/assets/` 为绝对前缀（或写 `<base href>`），前端 `DEFAULT_BASE`、`createBrowserRouter({ basename })` 都读同一个全局；或放弃路径前缀、dev 用子域。无论选哪种，补一条"同一 dist 在 `/` 与 `/dev/` 各访问一次首页 + 一次深链接"的冒烟用例。
- **置信度**：高（grep + vite.config.ts + dist/index.html 实测）

## F04 | blocker | 部署与开发流程.md:29,44,66-74 · forum/cmd/forum/main.go:12

- **问题**："promote 默认不重建 ⇒ 发的就是验过的"这条保证有三个洞：① promote 只比对**版本号**，没有任何地方比对"dev 部署时记录的制品 sha256 == promote 用的制品 sha256"；② `deploy.ps1 promote` 的子命令里没有 migrate，而 §2 又说迁移在启动前执行 —— schema 变更一旦发生，"回滚=换 current 链接"会把旧二进制指到新库（迁移是 append-only，没有 down 路径），且 promote 前没有 pg_dump；③ 运行中的版本号目前是 `main.go` 里的 `const version = "0.1.0-dev"`，文档没有规定它如何被注入成制品版本（ldflags？），这一条本身仍靠人。

- **置信度**：高（文档对读 + main.go 实测）
