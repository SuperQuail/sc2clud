# 部署与开发流程（保留老设计，重写实现）

> 老站的这套**设计**是对的：**两台实例、先在 dev 上验、验过才 promote 到生产、生产数据只读快照进 dev**。
> 坏的是它的**实现**：跨机手工接力、70 多个一次性脚本、nginx sub_filter 改前缀、编译期嵌入导致的构建顺序陷阱、拿生产当测试环境。
> 本文档保留设计、重写实现。排期见 `施工计划.md`（S0 与 S8 依赖本文档）。

---

## 1. 保留的四条（不许动）

| # | 老设计 | 为什么保留 |
|---|---|---|
| 1 | **双实例**：生产与 dev 各跑一个进程、各自的数据 | 在生产上做交互测试是旧站最贵的一课：测试脚本改生产口令、直插直删生产库 |
| 2 | **一条命令发 dev，只重启 dev** | 生产继续跑旧版本，随时可对照 |
| 3 | **验证通过后才 promote 到生产** | 两道关是真的两道关，不是「直接推生产再回滚」 |
| 4 | **生产数据只读快照进 dev** | dev 上跑的是真形状的数据；反向同步**绝对禁止** |

**外加一条前端规矩（同样保留）**：涉及界面改动，**先出真实渲染图再交付**，不许拿空壳截图当预览（见 §5）。

## 2. 改掉的六条（老做法 → 问题 → 新做法）

| 老做法 | 问题（复盘证据） | 新做法 |
|---|---|---|
| 本机构建前端 → scp → 服务器再编译（编译期嵌入静态产物） | 根因 10：顺序写死在注释里，踩过「新面板全 404」 | **一次构建出一个不可变制品**，部署只是「解包 + 切换 + 重启」 |
| 根目录 70+ 个一次性 `.sh`/`.ps1` | 每个脚本自带生产 IP、明文口令；无人知道哪个还能用 | **一个脚本，五个子命令**：dev / promote / sync / rollback / status |
| nginx `sub_filter` 给 `/dev/` 补前缀 | 应用里不能写 /dev，模板与前端要额外适配 | **一次构建，运行期 base**：Vite `base: './'` + Go 注入 `window.__BASE__` + Router basename + api client 同源前缀。**不再有 sub_filter** |
| 编译期内嵌迁移，增量编译下要 touch 才重编 | 新增迁移可能不生效，靠人记 | 迁移文件在制品里，`forum migrate` 启动前执行；**版本不一致拒绝启动** |
| 部署完靠人点页面确认 | 「改了没生效」反复出现 | 部署脚本内置**自检**：版本号一致、`/healthz` 版本匹配、首屏资源 200、迁移版本一致；任一失败**自动回滚** |
| CI 只跑 main 分支 | 根因 11：开发分支领先 193 个提交，门禁全程没跑过 | 门禁在**每次 push / PR** 上跑，不看分支名 |

## 3. 新实现

### 3.1 制品（唯一的部署单位）

一次构建产出：

    forum-<version>.tar.gz
      ├── bin/forum              # 静态链接的 Go 二进制
      ├── web/dist/              # 前端产物（index.html + assets）
      └── VERSION                # <git short sha>[-dirty] + 构建时间

- **服务器不构建**：制品在哪台机器构建都一样（CI 或本地），校验 sha256 后上传。
- **版本号就是制品名**：`/healthz` 与 `/readyz` 都返回它。部署后第一件事是核对运行中的版本 == 刚发布的版本——这一条能灭掉整类「改了没生效」问题。
- 构建一次，**dev 与生产用同一个制品**：所以 dev 上验过的就是生产要跑的，不存在「预览专用版本」。

### 3.2 实例与目录

    /srv/sc2clud/prod/
      ├── releases/<version>/        # 每次部署解一个新目录（保留最近 3 个）
      ├── current -> releases/<v>    # 符号链接，回滚就是换链接
      └── web/dist/                  # 与 current 一起切换
    /srv/sc2clud/dev/                # 同构，端口与库都不同
    /etc/sc2clud/prod.env            # 600，只有密钥与 DSN
    /etc/sc2clud/dev.env

- **两个 systemd unit**：`sc2clud-prod` / `sc2clud-dev`。**不允许 drop-in 覆盖 ExecStart**（旧站踩过：改完 unit 跑的还是旧二进制）——需要改就用仓库里的 unit 文件，改完 `daemon-reload`。
- **两个数据库**：`forum` 与 `forum_dev`（两个库、两个角色）。这比 SQLite 时代拷文件干净得多，也让「快照进 dev」变成一条 `pg_dump | pg_restore`。
- **两个 Cookie 名**（同域部署时）：`forum_session` / `forum_dev_session`，沿用后端方案 §9.2 的决策。若改用子域（`dev.example.com`），Cookie 天然隔离，这条可以退化成同一个名字——**二选一，写进 S8**。

### 3.3 部署脚本（一个，不是七十个）

    deploy.ps1 dev             # 构建 → 校验 → 上传 → 解包 → migrate → 自检 → 只重启 dev
    deploy.ps1 promote         # 把「已经在 dev 上验过的那个版本」装到生产（默认不再构建）
    deploy.ps1 sync            # pg_dump 生产 → 恢复到 forum_dev；图片目录 rsync 单向
    deploy.ps1 rollback prod   # current 指回上一个 release 并重启
    deploy.ps1 status          # 两个实例的版本、健康、迁移版本、磁盘

规则：

- `promote` **默认不重新构建**：升的是 dev 上那个制品，输入的版本号必须与 dev 当前版本一致，不一致直接拒绝（这是「验过才发」的机器保证，不靠自觉）。
- 每个子命令结束时打印**运行中的版本**与自检结果，不打印「成功」这种无法核验的话。
- 脚本里**不得出现生产 IP、口令、密钥**：这些只从 `/etc/sc2clud/*.env` 或部署机的密钥存储读。

### 3.4 dev 快照（sync）

    pg_dump -Fc 生产库 → scp → pg_restore --clean --if-exists 到 forum_dev
    rsync 生产图片目录 → dev（--delete）

- **单向**：dev → 生产**没有任何路径**（脚本里根本不提供这个方向）。
- 快照后 dev 上的账号口令仍是生产的（同一份哈希），所以 dev 登录用**测试专用账号**；**禁止在 dev 上改别人口令**（旧站的测试脚本正是这么干的）。

### 3.5 前端界面改动的交付规矩（保留老规矩）

1. **必须真实渲染**：起真的 dev 实例、真数据（sync 来的快照）、真浏览器整页截图。
2. **不许空壳**：截图里必须有同页面的其它内容（顶栏、列表、侧栏、页脚）；脚本断言「有真实数据」，判为空壳就退出码 1。
3. **预览与上线没有第二套代码**：同一制品、同一份数据。
4. **≥3 种方案**：除非改动非常明确单一（例如「把这个按钮改红」），都要给 3 套方案 + 各自的一句话取舍，由人挑。
5. 出图工具按需装（Playwright 只在出图时装，不进主依赖），**不改产品代码**。

### 3.6 CI

| 触发 | 跑什么 |
|---|---|
| 每次 push / PR | 后端：gofmt、go vet、golangci-lint、go test（含数据库文档 §12 的 11 条自检 + 迁移一致性）；前端：pnpm check（typecheck、lint、test、体量门禁、体积门禁） |
| 打 tag | 构建制品、附 sha256、上传到发布目录 |
| 手动 | `deploy dev` / `deploy promote` |

**门禁必须跑在会合入的分支上**（老站的 CI 只跑 main，而开发在 dev-side 上领先 193 个提交——等于没跑）。

## 4. 与旧站的对照（一句话）

    旧：本机构建 → scp → 服务器编译（顺序靠人记）→ 手动点页面确认 → 出问题靠 curl 猜
    新：一次构建一个制品 → 版本号写进 /healthz → 部署脚本自检 + 失败自动回滚 → dev 验过才 promote

## 5. 开工前要定的

| 编号 | 事项 | 默认建议 |
|---|---|---|
| D1 | dev 用**路径前缀**（`/dev/`）还是**子域**（`dev.example.com`） | **已改判：用子域**（盲审 F01）。路径前缀要在四处做运行期 plumbing（Router basename / API 前缀 / 资源 URL / Cookie 名），而这正是旧站头号 bug 类；子域一次性消掉前缀、sub_filter 与双 Cookie 名三样东西。代价：dev 需要一个域名 |
| D2 | 服务器是否已装 PostgreSQL（2 核 2GB） | 装本机 PG，`shared_buffers=256MB`；不引入 Docker |
| D3 | 制品从哪构建（CI 还是开发机） | 有 CI 就用 CI；没有就开发机构建后上传，但**制品只有一个来源** |
| D4 | 出图工具（Playwright）装在哪 | 开发机按需装，不进主依赖、不进服务器 |
| D5 | 域名与证书现状（旧站长期无证书，导致 Secure/SameSite 行为无法验证） | S8 前必须有 https，否则 §9.2 的 Cookie 决策无法验证 |
