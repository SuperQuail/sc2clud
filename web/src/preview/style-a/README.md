# 方向 A · 信息密度优先

给每天都来的老用户：一屏尽量多放主题、少装饰、强对齐，靠扫读而不是靠浏览。
两个变体在 `web/src/preview/style-a/`，各自自包含（假数据 + 组件 + 布局），默认导出页面组件。

| | v1.tsx「工作台」 | v2.tsx「密度墙」 |
|---|---|---|
| 版式 | 双行行式 + 右侧信息栏（版块 / 热帖 / 站点） | 单行制表 + 无侧栏，全宽 |
| 一屏条数（1080p） | ~13 条 | ~23 条 |
| 封面 | 行首 56×40 缩略图，无封面留空槽保证列对齐 | 标题前 20×14 小图，只在有封面时出现 |
| 版块导航 | Ring UI Tabs（溢出自动折叠成 more 菜单） | Ring UI 按钮组，横向滚动条 |
| 顶栏 + 工具条 | 44 + 36 px | 36 + 32 px |

## 取舍

- **不用卡片**：卡片的内边距、圆角、阴影在同样像素里少放三成信息；改用 1px 分隔线 + 列对齐。
- **装饰只留三种功能标记**：类型（讨论 / 资源 / 转载）、置顶、精华，其余靠字重与对齐区分。
- **元信息只在读屏出现**：视觉只留图标 + 数字（重复 20 遍「回复 12 赞 3」是噪声），指标名放 `sr-only`。
- **标题整行可点**：`after:inset-0` 把标题链接铺满整行，命中面积大；作者 / 版块链接再抬到上层。
- **宽度换密度**：≥1200 才给 v1 上右栏；<768 收掉封面与数字列，作者与计数落到标题下第二行，标题不缩水。

## 库与令牌

- **控件全部来自 Ring UI**：Button、ButtonSet（排序 / 状态切换）、Input（搜索）、Tabs + Tab（版块导航）、Toggle（深浅色）、Avatar、Tag（类型 / 置顶 / 精华）、Panel、ErrorMessage、LoaderInline。
- **Tailwind 只做布局、间距、响应式**；颜色一律走 `tokens.css`，无写死色值。自建件只有骨架屏与空状态（§7.2 允许自建，落地时应进 `src/ui/`）。列表内的标题与文字链接用原生 `<a>`：§7.2 控件表不含 Link。
- **令牌覆盖**：容器内把 `--muted-foreground` 由 62% 提到 72% 混色，11–12px 元信息对比度从临界 4.5:1 拉到约 6:1；全局令牌未改。

- **无障碍**：语义标签、`:focus-visible` 焦点环、图片有 alt、图标 `aria-hidden`、开关带 `aria-pressed`、错误态 `role="alert"`、骨架 `aria-busy` + 可见加载文案。

## 场景

- **v1**：首页要同时承担导航与发现（右栏放版块索引与热帖），标题长、需要两行。
- **v2**：`/b/:slug` 这类「只看这个版块」的列表页，或用户把密度拉满时；屏幕越宽收益越大。
- **不建议**：v2 的 36px 行在触屏上偏挤，<768 建议用 v1 的两行式。

## 预览

工具条右侧的「预览状态」（列表 / 加载中 / 空 / 错误）是给评审看四态的开关，不是产品功能。假数据 20 条，形状照抄后端方案 §21.3；封面是目录内的占位 SVG（真实数据是 `/img/<hash>`）。
